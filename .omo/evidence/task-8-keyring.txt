PAT STORE (spec: service "passm", user "github-pat", keyring 4.1.x)
-------------------------------------------------------------------
trait PatStore: Send + Sync {
    fn get(&self)    -> Result<Option<String>, SyncError>;
    fn set(&self, pat: &str) -> Result<(), SyncError>;
    fn delete(&self) -> Result<(), SyncError>;
}
- KeyringPatStore::new() -> keyring::Entry::new("passm", "github-pat")
- get(): NoEntry -> Ok(None); other errors -> SyncError::KeyringError
- set()/delete(): errors mapped to SyncError::KeyringError
- Android: NOT enabled in Cargo.toml (would break linux/macos). T16 wires
  features = ["android-native-keyring-store"] + Kotlin
  io.crates.keyring.Keyring.initializeNdkContext(context) in
  MainActivity.onCreate (Tauri 2.11+ removed automatic ndk-context init).
  Documented in pat_store.rs doc comment.

DEVICE ID (spec: UUIDv4 persisted to <app_data>/device_id)
----------------------------------------------------------
- load(dir): read + trim + UUID-parse validate; NotFound -> Ok(None);
  invalid content -> SyncError::InvalidDeviceId (rejected, not regenerated -
  a corrupt file is a red flag, silently replacing it would lose identity)
- load_or_create(dir): existing -> return; else create_dir_all + fresh
  UUIDv4 + write
- Path is injected (no hardcoded data_dir; Tauri layer resolves app_data_dir
  in T11)

DESIGN NOTES
------------
- PAT never touches disk in any code path (keyring or MockPatStore only).
- device_id invalid-content policy: ERR (InvalidDeviceId), do not
  auto-regenerate - preserves device identity integrity for merge tiebreak.
- Windows feature set to windows-native-keyring-store per spec (Credential
  Manager); the crate keeps the workspace-level git2 dep ready for T9.
