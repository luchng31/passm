=== API (crates/passm-vault/src/lib.rs) ===
pub fn merge(local: &Vault, remote: &Vault) -> Vault
- Pure function, no I/O. Per entry id:
  1. higher version wins
  2. equal version + one tombstone (deleted=true) -> tombstone wins (no-resurrect)
  3. equal version + both live -> lexicographically higher device_id wins
  4. entry present on only one side -> taken as-is
- Implemented as a total order (entry_cmp) over same-id entries:
  version, then deleted (true > false so tombstone wins), then device_id,
  then remaining fields (title/username/password/url/notes/created_at/
  updated_at) to break full ties deterministically. Winner = max under the
  order -> commutative by construction (max(a,b) == max(b,a)).
- Result entries sorted by id (canonical), so merge(a,b) == merge(b,a)
  holds both as canonical_json bytes AND as Vault structs (PartialEq).
- No unwrap/panic in non-test code.

=== Property tests (seeded, deterministic) ===
- merge_is_commutative_and_idempotent_randomized: StdRng::seed_from_u64
  (rand 0.8, workspace dep, added as dev-dependency), 50 iterations.
  Each iteration builds two random Vaults over a shared 8-id pool with
  random versions (1..=5), device_ids (dev-0..dev-2), deleted flags
  (30%), and content. Asserts:
    canonical_json(merge(a,b)) == canonical_json(merge(b,a))   [convergence]
    canonical_json(merge(merge(a,b), b)) == canonical_json(merge(a,b))
    canonical_json(merge(merge(a,b), a)) == canonical_json(merge(a,b))
                                                               [idempotence]
- Deterministic rule tests (both argument orders):
  - disjoint merge: all 4 entries from both sides present
  - higher version wins both directions (v3 beats v1)
  - equal-version live tiebreak: device "dev-b" beats "dev-a", same winner
    in reverse order (commutativity)
  - equal-version tombstone beats live, same in reverse (no-resurrect)
  - tombstone v5 vs live v3 -> tombstone stays (no resurrection)
