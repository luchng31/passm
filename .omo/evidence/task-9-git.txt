PAT CREDENTIAL HANDLING (security)
----------------------------------
- Cred::userpass_plaintext("x-access-token", pat) inside a RemoteCallbacks
  credentials closure, set on BOTH fetch and push options (and RepoBuilder
  fetch_options for clone).
- PAT is NEVER embedded in the remote URL -> cannot leak into .git/config.
- ensure_clone also repairs a pre-existing origin whose URL drifted from the
  expected remote_url (defense against a PAT-embedded URL from older code).
- Callback path exercised by unit test calling the closure directly with a
  fake https URL and asserting the produced Cred has a username and
  USER_PASS_PLAINTEXT credtype.

DESIGN NOTES
------------
- Module-global REPO_DIR: Mutex<Option<PathBuf>> (NOT OnceLock) so a re-clone
  can repoint it; set by ensure_clone, read by open_repo(). T10 drives these
  free functions from a single-threaded sync engine.
- git_repo tests are serialized via a shared TEST_LOCK Mutex because they
  share the global REPO_DIR; parallel execution made one test operate on
  another test's (already-deleted) tempdir -> "No such file or directory".
- Deterministic commit identity: Signature::now("passm", "passm@local")
  (git2 0.21 has no Time::now(); Signature::now is the equivalent).
- Reference::shorthand() returns Result<&str, Error> in git2 0.21 (not
  Option) - call .ok() first.
- Tail-expression temporary gotcha: `match repo.head() { ... }` as a function
  tail keeps the temporary Reference alive past `repo`'s drop -> E0597; bind
  the match result to a local first.
- checkout_vault_file reads the WORKING TREE (not HEAD tree) so T10 sees
  post-merge content before committing.
- safe_rel_path rejects absolute paths and ".." traversal.
